## 1. 今回の総合判定
**条件付きGO／独自プロトコルの新規性未確立。** 今回の一次資料では、認証用JWTの期限が切れても確立済みライセンスセッションが継続する構成が確認できた。したがって、認証トークンの期限切れ、発行権Lease満了、既発行利用権の実失効を同一イベントとして扱う安全性主張は成立しない。これは製品の欠陥を意味しない。

## 2. 今回新たに確認した重要事項
Thales公式「XML Tags for the Config Function」は、Sentinel EMSのJWT access tokenが失効しても、事前に成功したログインセッションは有効のままと説明する。https://docs.sentinel.thalesgroup.com/ldk/LDKdocs/Tbox/Licensing_XML_Tags/HASP_CONFIG_XML_Tags.htm
同社「Scope Input XML Tags」は die_at_expiration=0（既定）ではセッション継続を許し、1では期限後のセッション終了を指定できると説明する。https://docs.sentinel.thalesgroup.com/ldk/LDKdocs/API-licensing/Licensing_XML_Tags/Scope__XML_Tags.htm
これらは認証資格情報の寿命と実利用権の寿命が別物であることの直接的な製品仕様例である。ただし前回までに「期限後セッション継続」自体は既知であり、今回の追加確認点は**JWT期限とログインセッションの分離**である。

## 3. 先行研究・既存方式との比較
O'Neil Escrow、Chubby、Bounded Counter CRDT、Indigo、Mobisnap、Exo-leasing、Coordination Avoidanceは権限分配・fencing・調整回避の既知比較対象。Keygen Relay、FlexNet、Sentinel LDK、CodeMeter、Autodeskは既存のデジタル利用権管理手段である。今回、各原著を新規精読したわけではなく、それぞれにJWT/セッション競合の欠陥があるとは断定しない。研究の正式比較はC0=中央接続必須、C1=事前Lease・代替回線なし、C2=事前Lease＋短文失効証拠、強いC3=同一代替回線を使う認証付き返上・状態照会である。C2/C3の認証・失効・証拠・回線条件は等しくする。

## 4. 社会的需要の評価
複数拠点CAD/CAE/GISのフローティングライセンスにおける安全な再配分は適用候補。既存公式文書はオフライン借入や期限後の利用継続を示すが、通信分断下で旧拠点Aの残存権利が新拠点Bの発行停止を生んだE1型の実事故、頻度、被害額の直接証拠は今回得られていない。社会的需要はなお限定的な根拠にとどまる。

## 5. 新規性を否定し得る証拠
JWT失効とセッション存続の分離は既存製品が扱う既知の契約であり、この区別だけでは独自性にならない。既報の50合成トレースではC2と強いC3の平均管理起因待機はともに7.72 tick（差0.00）だが、今回は再実行していない。既存方式と同じ失効強制能力を与えたときにC2だけが短縮できる条件は未確立。

## 6. 新たな設計上の欠陥・反例
**未検証の反例候補：** 拠点Aの端末Xは時刻t0にJWTでログインし、継続セッションを確立。t1にJWTが失効し、中央がそれを「旧利用権失効の証拠」と誤認してBへ発行権を移す。t2でXの実行中セッションが有効なら、B側の新利用権と同時利用となり得る。
必要前提：認証トークン期限だけを移譲根拠とし、実セッションの終了・アクセス拒否を確認しないこと。
対策：auth_token_valid、issuer_lease_valid、license_entitlement_valid、runtime_session_active、revocation_enforcedを別状態とし、発行停止・in-flight閉包・旧利用の実失効を移譲条件に含める。
限界：クライアントが失効を強制しない構成では、中央のJWT期限確認だけでは安全な早期移譲を証明できない。現行研究コードにこの欠陥が実在するかは未確認。

## 7. 改善仮説（未検証）
### H1：認証期限と実利用終了の分離
1. 課題：JWT期限切れを実利用停止と誤認する。
2. 案：認証・発行権・ライセンス・セッション・強制失効を独立状態にし、移譲前に実利用終了の信頼できる証拠を要求。
3. 既存との差分：既知のライセンス実装契約を形式モデルへ適用するもので、新規性は未確立。
4. 公平ベースライン：C2と強いC3へ同じJWT寿命、クライアント実装、証拠、通信路を付与。
5. 指標：同時利用違反、管理起因待機、棄権率。
6. 実験：JWT期限とセッション期限を独立に変動させ、時刻逆転・ACK喪失も注入して有限探索。
7. 棄却：安全違反が残る、またはC3に対する追加保証・有効性がない。

### H2：失効契約別の可用性境界
1. 課題：実行中セッションが終了しない場合に早期移譲可能と誤認する。
2. 案：ログイン時のみ検査、周期検査、操作ごと検査、強制停止・drainを別契約として待機時間の安全下界を計算。
3. 既存との差分：既存製品の設定差を公平な比較条件へ反映する評価研究案である。
4. 公平ベースライン：C2/C3の検査頻度・失効強制・時計誤差を同一にする。
5. 指標：安全な移譲時刻、管理起因停止、通信量、失効後アクセス残存時間。
6. 実験：同一障害列を各契約に適用し、失効不能な契約では安全な早期移譲を棄権扱いにする。
7. 棄却：強制失効の上界を保証できない、またはC2の優位が再現しない。
